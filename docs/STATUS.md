# Статус CVTL

Дата — 10.11.2026. Расчёты M2 проверены локально. Физическое ядро M1 и каркас M0 подтверждены на Ubuntu 22.04 LTS. Полнота базы материалов остаётся открытой по `cp(T)` Al 1100.

## Сделано

- Rust-workspace с границами крейтов из §12.1 ТЗ. `cvtl-core` разбирает и проверяет YAML и задаёт типы величин СИ. `cvtl-daemon` проверяет конфиг при запуске и завершается.
- M1. Модель тела в энтальпийной форме, четыре типа мостов, смена параметров с `dH_event`, запрос мощности в двух режимах и баланс насадки. Принятые соглашения и допуски описаны в [ADR 0005](adr/0005-thermal-model.md).
- Каталог M1 включает 10 кривых NIST для пяти материалов. Для OFHC указан `RRR=100`, для G-10 CR выбирается направление теплопроводности. Для Al 1100 доступно `k(T)`. [Каталог, источники и применимость](../data/materials/README.md)
- M2. Реализованы расчёт проводки с джоулевым теплом и опциональным излучением, расчёт номинальной области Keithley, подбор нагревателей и автономные команды `wire` и `heater-advisor`. CLI агрегирует потоки по узлам и выводит сценарный диапазон по вариациям `k(T)` и длины. [Модель и допуски](adr/0006-wire-and-envelope.md), [примеры CLI](../README.md#автономные-расчёты-m2)
- Поставляемый конфиг задаёт `hardware_enabled: false`, отключённые ветви и `null` для порогов и лимитов. Попытка включить аппаратный режим отклоняется.
- Четыре сопоставимых варианта GUI на одинаковых синтетических данных. Для следующего этапа GUI предварительно выбраны Svelte + uPlot по размеру сборки. Критерии и исходные замеры — в [ADR 0001](adr/0001-gui.md).
- Четыре ADR по [GUI](adr/0001-gui.md), [конфигу](adr/0002-config-format.md), [данным](adr/0003-run-data.md) и [транспорту](adr/0004-keithley-transport.md). CI настроен на Ubuntu Linux 22.04 LTS.

## Проверено

- M2. До реализации три CLI-теста дали ожидаемый отказ на заглушке. Попытка собрать аналитические тесты проводки и envelope остановилась на отсутствующих API. После реализации на macOS ARM64 с Rust 1.94.1 прошли `cargo fmt`, сборка, Clippy с `-D warnings`, запуск с конфигом поставки и полный набор из 41 Rust-теста. Из них 23 относятся к M2. Для всех четырёх кривых Lake Shore сверены опорные значения и диапазоны.
- M2. Медный эталон даёт 48,880933 мВт на `stage2` при нулевом токе. Проверены аналитические потоки к обоим концам, асимметрия при температурно-зависимом сопротивлении, выход за диапазон, радиационный баланс и суммирование по перехватам. Таблица §7 воспроизведена с допуском 0,1 Вт. Проверены сопротивление проводов, худший случай по диапазону нагревателя, границы тока и напряжения и ограничение мощности. При 40 Ом, `R_loop = 0` и коэффициентах 0,9 получено 32,4 Вт на канал и 64,8 Вт по двум каналам в расчётной области источника.
- M1. Аналитические тесты появились до реализации. Первый `cargo test --workspace --locked --no-run` завершился ожидаемой ошибкой отсутствующих API в `curves.rs` и `physical_references.rs`. После реализации прошли форматирование, сборка, Clippy с `-D warnings` и полный `cargo test --workspace --locked --offline` на macOS ARM64 с Rust 1.94.1. Итог — 18 тестов, в том числе два теста безопасного конфига M0.
- M1. Проверены экспоненциальное остывание, нагрев с переменной `cp`, знаки и аналитические потоки четырёх мостов, устойчивость жёсткого шага, границы кривых и атомарность ошибок. В тестах энергобаланса, включая сценарий с изменением энтальпии и расчёт для тела из меди OFHC, относительная невязка укладывается в `1e-6`. Кривые сверены с 30 опорными значениями опубликованных аппроксимаций NIST. Нулевое задание при отрицательном запросе проверено отдельно.
- M1. Ubuntu 22.04 LTS, коммит `988e1ec`. Прошли форматирование, сборка, Clippy, полный набор Rust-тестов, запуск с конфигом поставки и проверки четырёх вариантов GUI. [Успешный запуск CI](https://github.com/test1card/CVTL/actions/runs/42815684036)
- macOS ARM64, Rust 1.94.1. Прошли `cargo fmt --all -- --check`, `cargo build --workspace --locked`, `cargo clippy --workspace --all-targets --locked -- -D warnings` и `cargo test --workspace --locked`. Тесты проверили все поставляемые YAML-конфиги и отказ для аппаратного режима и некорректной конфигурации.
- Запуск `cvtl-daemon` с конфигурацией поставки завершается успешно. С `hardware_enabled: true` завершается с отказом.
- Четыре production-сборки GUI на macOS ARM64. Playwright проверил локальную загрузку ресурсов, SVG, переключение температуры и мощности и изменение графика в каждом варианте. Локальная среда для измерений — Node 26 и Chrome 156.
- Ubuntu 22.04 LTS, коммит `b348126`. Rust 1.94.1 прошёл форматирование, сборку, Clippy, тесты и запуск с конфигом поставки. Node 22 прошёл `npm ci`, сборку и браузерные проверки всех четырёх вариантов на Chromium 141 с `ru-RU`. [Успешный запуск CI](https://github.com/test1card/CVTL/actions/runs/42813246921)
- При исходном запуске uPlot завершался ошибкой форматирования чисел с локалью `en-US@posix`. Для сопоставимых условий в браузерном тесте зафиксирована `ru-RU`. [Диагностический запуск CI](https://github.com/test1card/CVTL/actions/runs/42812745553)

## Не проверено

- Изменения M2 на Ubuntu 22.04 ожидают CI после публикации.
- Свойства фактической проводки, неопределённость теплоперехвата и геометрии, сходимость по сетке для реального стенда. Сценарный диапазон учитывает заданные изменения `k` и длины. Полная оценка неопределённости относится к M8. Действительные пределы Keithley, параметры нагревателей и квантование уставки остаются открытыми. [A-04 и A-05](OPEN_QUESTIONS.md)
- Криогенная теплоёмкость Al 1100 / UNS A91100. Каталог возвращает `UnavailableProperty` для `cp(T)` до получения первичного источника. Отклонения аппроксимаций NIST приведены отдельно от неопределённости свойств конкретных образцов. [A-02](OPEN_QUESTIONS.md)
- Лабораторный ПК и его браузер проверяются отдельно от CI. Работа полного GUI с длительным обновлением графиков и нестандартными локалями остаётся в M7.
- Обмен с Keithley 2604B и Lake Shore 218S, работа PyVISA с конкретным бэкендом и GPIB–USB, карта каналов, независимое отключение и реакция на потерю связи. Физический доступ отложен до Фазы B. Протокол Maisheng остаётся `unverified`.
- Критерии M3–M9 по симуляторам приборов, управлению и защитам, журналу и реплею, рабочему GUI, оценке неопределённости и программе стенда. Отдельно открыты исходные данные и пределы из [реестра](OPEN_QUESTIONS.md).
