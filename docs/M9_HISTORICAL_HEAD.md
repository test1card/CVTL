# M9. Историческая характеристика головки

Офлайн-сценарий вычисляет характеристику KDE420SA по шести штатным точкам этапа I. Аргумент `T` задаёт температуру холодной ступени `stage2` в диапазоне 4,95–300 К. Результат содержит температуру тёплой ступени `stage1`, координату `P_net` и происхождение точки. Исторический `P_net` — опубликованная подведённая мощность в опыте без жидкого азота и экрана, с невычтенными паразитными притоками. [Опоры](../data/machines/kde420sa_stage1_data.csv) · [Транскрипция](../data/old_tests/kde420sa_stage_i_legacy.csv)

Точные опоры возвращаются с `historical_anchor` и номером строки. Между соседними опорами `stage1` и `P_net` интерполируются линейно с меткой `interpolated`. Выше последней опоры используется расчётная ветвь `synthetic`, параметры которой заданы для `test_only`.

```text
T0 = 23,4 К, D = 300 К − T0
stage1(T) = T + 20,4 К × (1 − (T − T0) / D)
P_net(T) = 22 Вт + (10/7 Вт/К) × (T − T0)
```

Продолжение сохраняет последнюю секущую мощности и уменьшает разность ступеней от 20,4 К до нуля. На стыке совпадают значения `stage1` и `P_net`. Производная `stage1` меняется. Во всех линейных интервалах `stage1 ≥ stage2`. При 300 К обе температуры равны 300 К, условный `P_net` составляет 417,142857 Вт. Эти значения относятся к самостоятельному синтетическому расчёту. Аппаратные пределы, команда нагревателя и `Q2_eff` определяются своими трактами. Форму продолжения предстоит сверить с владельцем физики.

На экране «Сценарий» нажать «Рассчитать характеристику». Таблица содержит шесть опор, пять средних точек и продолжение при 50, 100, 200 и 300 К. Ссылка сохраняет JSON с тем же расчётом, условиями и SHA-256 исходного CSV. При запущенном локальном демоне отчёт также доступен по `GET /api/historical-head` на напечатанном порту. Этот вызов оставляет подготовку A1 и текущий прогон в прежнем состоянии.

```sh
cargo test --locked -p cvtl-sim --test historical_head
cargo test --locked -p cvtl-sim --test m6_recording stage_i_row_7_latches_head_inversion_and_records_off -- --nocapture
npm --prefix ui run build:operator
npm --prefix ui run test:operator
```

Для проверки инверсии используется отдельная строка 7 из действующего импорта. Исторические `stage1=39,8 К`, `stage2=41,3 К` и опубликованные 34,1 Вт сохраняются с исходным смыслом. В тестовом контуре подаётся штатный запрос M6 0,75 Вт и меняется кадр термометрии. Строка 8 остаётся в импорте с исходной пометкой. Номинальная характеристика использует только строки 1–6.

На macOS в целевом тесте измерено 1,05 Вт перед инверсией. В отказном такте причиной стала `HeadInversion`. Записаны обе команды OFF, нулевые ответы выходов и `OffVerified`. Эмулятор показал нулевую мощность обеих ветвей. Повторные Arm и Start отклонены. Завершённый raw содержал 431 проверенную запись. Строка свидетельства сохранена в `t002-inversion.log`.

На macOS 27.2 ARM64 и Ubuntu 22.04.5 ARM64 с Rust 1.94.1 прошли форматирование, сборка, Clippy с `-D warnings`, по 296 тестов и запуск с конфигом поставки. Состав и SHA-256 исходников этапа I сохранены. Для архивов RECORDING v1, A1 v1, отдельной записи со сменой `scale` и M8 `run-01` совпали пять прежних JSON реплея и анализа.

Офлайн-сборка UI и полный браузерный сценарий прошли на обеих ОС с Node 22.23.4. Проверены 15 строк, скачивание того же JSON, отсутствие внешних запросов и размещение таблицы при 360 CSS px. Мобильная проверка измеряет ширину таблицы и проверяет каждое число на одной строке. Скачанные JSON обеих ОС совпали, SHA-256 `bf731f77bea9bf7dd6ffa20c8cc2f74972bd6d4774e924b93a09e243f2292020`. Обычный сценарий A1 прошёл 250 тактов, смену параметров, подтверждённый OFF, реплей и M8. В обоих браузерных прогонах интервал оценки покрыл известные 4 Вт.

Журналы, сохранённые JSON и снимки обоих браузеров находятся в `.local/GRACE-M9-HISTORICAL-HEAD/`. Параметры реальной головки, паспортная характеристика и стендовая воспроизводимость остаются открытыми.
