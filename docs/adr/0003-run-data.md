# ADR 0003. Формат данных прогона

Статус — принято в M0. Запись и реплей реализуются в M6.

## Решение

Сохранить структуру §12.4 [ТЗ](../../TZ.md). В каждом каталоге `runs/…` находятся `config.snapshot.yaml`, `raw.ndjson.zst`, `events.ndjson`, `meta.json`, `derived/` и `report.html`. Один объект JSON на строку UTF-8 даёт последовательное чтение и проверку записей. `raw` хранит первичные отсчёты, команды, ответы и все входы реплея, включая изменения параметров в порядке применения. `events` хранит операторское представление событий с привязкой к `raw`. Производные величины и экспорт CSV/Parquet строятся отдельно. [Формат JSON Lines](https://jsonlines.org/)

Записи получают номер последовательности и монотонное время. Календарное время сохраняется для привязки к журналу опыта. `meta.json` фиксирует версию схемы, версию программы и хэши снимка и использованных баз. Для реплея сохраняется доступ к точным версиям справочных данных. При несовпадении версии или хэша результат помечается как невоспроизводимый до восстановления исходного набора.

`raw` состоит из независимо декодируемых кадров Zstandard. Кадр заканчивается на границе записи, несёт контрольную сумму и периодически сбрасывается на диск. Реплей принимает завершённые проверенные кадры. Оборванный хвост помечается как неполная запись. Ошибка контрольной суммы в уже записанной части требует отдельной диагностики. Граница гарантированного хранения определяется завершённым сбросом на диск. [RFC 8878, §3.1](https://www.rfc-editor.org/rfc/rfc8878.html#section-3.1)

## Варианты

Несжатый NDJSON удобен для просмотра, но требует больше места. Один длинный кадр затрудняет проверяемое восстановление после обрыва. CSV пригоден для экспорта плоских рядов, а Parquet — для анализа столбцов. Для первичного журнала выбраны структурированные записи с последовательной записью и независимыми кадрами.

## Приёмка в M6

Проверить реплей по снимку и `raw`, порядок отсчётов и операторских событий, совпадение результатов в заранее заданных допусках, сбой записи и восстановление завершённых кадров после прерывания. Переполнение очереди или ошибка журнала передаётся в защиты. До M6 формат зафиксирован на уровне решения.
