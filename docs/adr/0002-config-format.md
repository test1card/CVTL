# ADR 0002. Формат конфигурации

Статус — принято в M0.

## Решение

Конфигурация — один YAML-документ в UTF-8. Схема `schema_version: 1` начинается с примера из §12.3 [ТЗ](../../TZ.md). Десериализация выполняется `yaml_serde` и Serde в типы Rust. Неизвестные поля, ошибки типа и неподдерживаемая версия дают ошибку до запуска. [Проект yaml_serde](https://github.com/yaml/yaml-serde)

YAML поддерживает `null` для незаполненных параметров и комментарии для оператора. TOML потребовал бы отдельного соглашения для пустых значений. JSON сохраняет `null`, а пояснения к редактируемому вручную конфигу пришлось бы хранить отдельно. Схема задаёт единицы в именах полей. Публичные интерфейсы, выполняющие расчёт, получают величины с типами единиц.

Конфигурации поставки хранятся в `config/`. Аппаратные адреса, карта датчиков и пороги по умолчанию не заданы. `hardware_enabled: false`, `run_permission: unapproved`, ветви отключены. В отличие от примера §12.3, `age_max_s` остаётся `null` в поставке. Значение 1,5 с из ТЗ относится к испытательному сценарию `test_only`. Конфиг Фазы A с `hardware_enabled: true` отклоняется даже при заполненных полях. Выбор физического транспорта требует отдельного допуска и проверки профиля прибора.

## Проверка и развитие

В M0 проверить все поставляемые конфиги, отказ при попытке включить аппаратный режим и ошибки схемы. При развитии формата сохранять тесты старых версий. Для реплея сохранять снимок реально применённых параметров с версией и хэшем согласно [ADR 0003](0003-run-data.md).
